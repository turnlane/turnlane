# D-093 タスクと予定を分ける: 確認と入れ替えの手順

タスク（時間ブロックを含む）は Turnlane の中だけにし、カレンダーには書かない。予定は Turnlane から作る・動かす・伸ばす・
消す・題名とカレンダーを変えると、Calendar.app のデフォルトカレンダーへ書く（ADR 0012、phase0-plan 4.5 の
「D-093 の方式」、ux-mvp 4.12・4.13・7章、m2-api 24章）。以前の版（M3-3）がタスクの時間ブロックとして書いた予定は、
利用者が件数と期間を確かめてから消す（自動では消さない）。

- 作る先: Calendar.app の 設定 > 一般 > デフォルトカレンダー（D-072 と同じ解決）。目印は `url = turnlane://event/<uuid>`
- Turnlane から編集できる予定: 書き込めるカレンダー・参加者なし・繰り返しでない・終日でない（Turnlane で作った予定も同じ条件。
  Calendar.app で参加者を足したら読み取り専用になる）。それ以外はパネルに理由と「Calendar.app で開く」
- 作り分け: デイビューは予定のレーンのドラッグ = 予定、自分のレーン = タスク。3日ボード・週表示はドラッグ後の入力欄の
  「タスク / 予定」（Tab、既定はタスク）。`⇧C` と ⌘K の「予定を作る」（入力の時刻で作る: `Lunch 12:00 1h`）
- 削除の対象: `url` が `dayline://timeblock/` で始まる予定だけ。Turnlane で作った予定（`turnlane://event/`）・目印の無い予定
  （`url` が落ちたものを含む）には触れない。判定はヘルパ（0.4.0 の `listTimeblockEvents` / `deleteTimeblockEvent`）が行う

自動で確かめられる部分は `bun run check`（偽のカレンダーで作成・編集・削除・削除の対象の判定・時間ブロックを書かないこと）、
`bun run check:helper`（ヘルパを `--fake-store` で動かし、0.4.0 の RPC が WebSocket 越しに通ること。EventKit には触れない）、
`bun run e2e`（`events` スイート: 予定の作成・移動・伸縮・題名・削除、タスク / 予定の切り替え、`⇧C`）。

## ダミーデータで見る

```sh
bun run build:web
bun scripts/dev-board.ts --lang ja
```

- デイビューの予定のレーンの空白をドラッグ → 「予定 · Work に作成」の入力欄（Work の色）→ ⏎ で予定
- 3日ボードの今日の Plan レーンをドラッグ → 入力欄の上の「タスク / 予定」。Tab で予定に、もう一度 Tab でタスクに
- 会議（Weekly sync・Design review・Interview など）は参加者ありで読み取り専用。10/6 の Dentist は参加者なしで動かせる
- 設定 > カレンダー: 「新しい予定の書き先: Work · Example」、「カレンダーに書いた時間ブロック」に 2件（ダミー）と削除のボタン

## オーナーの手順

### 1. デーモンと UI の入れ替え（DB のマイグレーション 0007 あり）

```sh
cd ~/source/dayline
git pull               # main
bun install
bun run check
bun run build
bun run smoke
out/turnlane self-install    # デーモンを入れ替える
```

- 0007 は `calendar_event` に列を足し（予定のキャッシュなので次の同期で埋まる）、役割が「時間ブロックを書く」だった
  カレンダーを「無視する」にする。適用の前に DB のバックアップを自動で取る
- 入れ替えた時点で、タスクの時間ブロックはカレンダーに書かなくなる。ヘルパが 0.3.0 のままの間は、予定はすべて
  読み取り専用で、予定の作成は「カレンダーヘルパが古い」と出て失敗する（他の機能は動く）

### 2. カレンダーヘルパの入れ替え（→ 0.4.0。必要）

予定の作成・編集と、時間ブロックの予定の削除は 0.4.0 からの機能。S1 と同じ証明書で署名し直す（同じ証明書なら TCC の
許可はそのまま残る。D-053）。

```sh
security find-identity -v -p codesigning          # S1 で使った「Apple Development: …」を確かめる
TURNLANE_CODESIGN_IDENTITY="Apple Development: <名前> (<ID>)" bun run build:helper
bun scripts/check-calendar-helper.ts --skip-build # 任意（上でビルドした .app を一時 HOME で確かめる。EventKit には触れない）
turnlane calendar install --app out/TurnlaneCalendarHelper.app
turnlane calendar status
```

- `turnlane calendar status` の1行目が `Helper: 接続中 0.4.0 · 権限: フルアクセス`、`Events: Calendar.app のデフォルト → <カレンダー名>（<アカウント>）`
- 権限が「未決定」「拒否」に戻っていたら `turnlane calendar authorize`（ダイアログ）か、システム設定 > プライバシーとセキュリティ > カレンダー で TurnlaneCalendarHelper を「フルアクセス」に
- 順番は 1 → 2（デーモンが先）。逆でも壊れないが、古いデーモンが 0.4.0 のヘルパに時間ブロックを書こうとして失敗を繰り返す（実害は無い）

### 3. 以前の版が書いた時間ブロックの予定を消す（任意。確認してから）

まず消さずに件数と期間を見る:

```sh
turnlane calendar cleanup-timeblocks --dry-run
```

```
時間ブロックの予定（dayline://timeblock/）: 12 件 · 2026-10-05 〜 2026-10-09
  Work（Example）: 12 件
turnlane で作った予定（turnlane://event/）と、目印の無い予定には触れません。
（--dry-run: 消していません。消すには turnlane calendar cleanup-timeblocks）
```

件数・期間・カレンダーが思っているとおりなら消す（`y` で確定。端末でないところから実行するなら `--yes`）:

```sh
turnlane calendar cleanup-timeblocks
```

設定 > カレンダー の「カレンダーに書いた時間ブロック」でも同じことができる（件数と期間 → 「これらの予定を削除…」→ 確認の
ダイアログ → 削除）。確認の後に件数が変わっていたら消さずに「数え直してください」と出る。探す範囲は今日の前後 365 日。

- スマホの Google カレンダーなどで `url` が落ちた時間ブロックの予定は、目印が無いので対象にならない（数えない・消さない）。
  残っていたら Calendar.app で手で消す
- 一部が失敗したら件数が出る。もう一度実行すると残りを消す

### 4. 確認項目（結果を PO に返す）

1. デイビューの予定のレーンの空白をドラッグして題名を入れる → 1分以内に Calendar.app のデフォルトカレンダーに同じ題名・時刻で出る。数分以内にスマホのカレンダーにも出る
2. その予定を Turnlane でドラッグして動かす・下端で伸ばす → Calendar.app でも動く・伸びる（予定は増えない）
3. 予定をクリックしてパネルで題名・開始・長さ・カレンダーを変える → Calendar.app に反映される。「予定を削除」で Calendar.app から消える
4. 3日ボード（または週表示）で今日の Plan レーンをドラッグ → 入力欄が「タスク」で開く。Tab で「予定」に変わり、入力欄がデフォルトカレンダーの色になる。⏎ で予定が作られる。Tab を押さなければタスク＋時間ブロック（カレンダーには出ない）
5. `⇧C`（または ⌘K の「予定を作る」）→ `ランチ 12:00 1h` → 12:00〜13:00 の予定
6. タスクを時間軸に置く・動かす・外す → Calendar.app に何も増えない・変わらない
7. 参加者のいる会議・繰り返しの予定・購読（祝日など）のカレンダーの予定はつかめず、パネルに理由と「カレンダーで開く」が出る
8. Calendar.app で Turnlane が作った予定を動かす → 1分ほどで Turnlane でも動く
9. 手順 3 の `--dry-run` の件数と期間、実際に消した件数。消した後に Calendar.app のデフォルトカレンダーで、ふだんの予定と Turnlane で作った予定が残っていること
10. 失敗したとき（トースト「予定を保存できませんでした」）は、出た一文と `turnlane calendar status` の内容を PO に返す
