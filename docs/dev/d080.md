# D-080: 確認手順

仕様は ux-mvp.md 4.4（勤務時間外）・4.7（通知の設定の文言）・6.2（キーボードの節の開閉）、desktop-shell.md 3.3（通知の許可の表示とボタン）、m2-api.md の `POST /api/desktop/notifications`。値と比は docs/design/README.md の「D-080」。

- **勤務時間外**: 薄い塗り＋斜線（`.dl-off`）。ライトは #E8E8E3＋黒 8%、ダークは #030304＋白 7%。45° の 1px を 7px 間隔。時間軸の共通部品 `GridBackground` だけで描くので、3日ボード・週表示・デイビュー・朝の計画 Step 3 がそろう
- **設定の文言**: 「勤務時間外の許可待ち / Approval requests outside working hours」。挙動は変えない
- **デスクトップアプリの通知**: 「通知: オン」/「通知: オフ — システム設定で Turnlane の通知を許可してください」＋「システム設定を開く」/「通知: 未設定」＋「許可を求める」。ボタンはデーモン経由（SSE の `desktop_notifications`）でアプリに渡し、アプリが OS の許可の要求・システム設定の通知の画面を開く。アプリは main が前面に来たときに許可を読み直し、変わったらデーモンが `desktop_status` を送って設定画面が取り直す。`turnlane desktop status` も同じ言い方
- **キーボードの節**: アコーディオン、既定は閉じる、開閉は端末ごとに覚える。`?` の一覧の「設定 › キーボード で変更」と ⌘K の「キーボードショートカットを変更」（`/settings#keyboard`）から来たら開く

## オーナーの入れ替え手順

```sh
cd ~/source/dayline
git pull               # main
bun install
bun run check
bun run build
bun run smoke
bun run build:desktop  # 通知の許可の「未設定」とボタンの受け取り（Rust の変更）。署名は docs/dev/desktop.md の 1 章
out/turnlane self-install    # デーモンと turnlane を入れ替え、out/Turnlane.app も ~/Applications に置き直す（マイグレーションは無し）
```

勤務時間外の見た目・文言・キーボードの節は、デーモンの入れ替えと開いているウインドウの再読み込み（⌘R）で反映される。通知の表示（オン / オフ）とオフのときの文言もデーモンだけで変わるが、「システム設定を開く」「許可を求める」のボタンと「未設定」の区別はデスクトップアプリの入れ替えが要る（古いアプリはボタンの指示を無視し、未決定を「確認中」と出す）。デーモンを先に入れ替える（新しいアプリの `not_determined` を古いデーモンは受け付けない）。カレンダーヘルパは入れ替え不要。

## 通知を有効にする

1. 設定 > デスクトップアプリの行を見る
2. 「通知: オフ」なら「システム設定を開く」を押す → システム設定の「通知」が開くので、一覧の Turnlane を選び「通知を許可」をオンにする（バナーの種類は「一時的」か「持続的」）。メニューバーの右クリックの「Notifications are off · Open System Settings」でも同じ画面が開く
3. 「通知: 未設定」なら「許可を求める」を押す → macOS の確認が出るので「許可」を選ぶ
4. Turnlane のウインドウに戻ると、アプリが読み直して「通知: オン」に変わる（変わらなければウインドウを一度切り替える）。`turnlane desktop status` でも「通知: オン」と出る
5. 夜も許可待ちを知りたいときは「勤務時間外の許可待ち」をオンにする（既定オフ）
