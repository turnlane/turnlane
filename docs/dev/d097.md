# D-096・D-097: 予定の取り消しと、会議前に聞く集中モード（確認と入れ替えの手順）

- D-096: 予定の移動・伸縮・題名・カレンダーの変更を ⌘Z で戻す（逆の書き込み。戻す前に予定がカレンダー側で変わっていたら
  戻さずに「予定がカレンダー側で変わっていたため、元に戻しませんでした。」）。予定の削除は確認のダイアログ（⏎ で削除、
  Esc でやめる）。ux-mvp 4.12・6章・7章、m2-api 24章の `ifMatch`
- D-097: 会議（参加者がいるか、会議リンクがある busy の予定）の開始の5分前に「集中モードにしますか？」と聞き、集中中は
  自分の番・許可待ちの通知を止め、終わったらまとめて1回知らせる。メニューバーと ⌘K から手動でも始める。ux-mvp 4.15、
  m2-api 25章、desktop-shell 3.5

自動で確かめられる部分は `bun run check`（判定・時刻・まとめ・閉店モードとの関係・API・設定）、`bun run check:helper`
（ヘルパ 0.5.0 の `hasMeetingLink`）、`bun run check:desktop`（通知の path の key、メニューバーの見た目の判定）、
`bun run e2e`（`events` スイートの ⌘Z と削除の確認、`focus` スイートの帯の問い・答え・⌘K）。

## ダミーデータで見る

```sh
bun run build:web
bun scripts/dev-board.ts --lang ja
```

- 予定を動かして ⌘Z → 元の時刻に戻る。予定のパネルの「予定を削除」→ 確認のダイアログ（Esc でやめる、⏎ で削除）
- 集中モード: ⌘K で「集中モード: 30分」→ 画面上部に `集中 · 13:50まで` と「終了」。設定 > 通知 に集中モードの5項目
- 問いの帯: 設定 > 通知 で「対象の予定」を「予定ありのすべて」、「何分前に聞くか」を 30 にして、デイビューで 13:40 頃に
  予定を作る → 画面上部に `13:40 … · 集中モードにしますか？` と「集中する」「しない」（ダミーにはデスクトップアプリが
  つながらないので帯で聞く）

## オーナーの手順

### 1. デーモンと UI の入れ替え（必要。DB のマイグレーション 0008 あり）

```sh
cd ~/source/dayline
git pull               # main
bun install
bun run check
bun run build
bun run smoke
out/turnlane self-install    # デーモンを入れ替える
```

- 0008 は `calendar_event.has_meeting_link` を足す（予定のキャッシュなので次の同期で埋まる）。適用の前に DB のバックアップを
  自動で取る
- 入れ替えた時点で、予定の ⌘Z・削除の確認・集中モード（帯・⌘K・設定）が使える。ヘルパが 0.4.0 のままでも、参加者の
  いる会議と、URL・場所に会議リンクがある予定は対象になる（メモの中の会議リンクだけは 0.5.0 が要る）

### 2. デスクトップアプリの入れ替え（必要。通知上のボタンとメニューバー）

```sh
bun run build:desktop                       # 署名は docs/dev/desktop.md の 1 章（TURNLANE_CODESIGN_IDENTITY）
turnlane desktop install --app out/Turnlane.app
```

- 入れ替えるまでは、問いの通知にボタンが無い（本体のクリックで main が開く）。答えはメニューバーのポップオーバー
  （常に問いを出す）か、通知の許可を外したときの画面上部の帯でできる
- 同じ証明書で署名すれば通知の許可はそのまま残る

### 3. カレンダーヘルパの入れ替え（→ 0.5.0。推奨。メモの会議リンク）

```sh
TURNLANE_CODESIGN_IDENTITY="Apple Development: <名前> (<ID>)" bun run build:helper
bun scripts/check-calendar-helper.ts --skip-build   # 任意（一時 HOME。EventKit には触れない）
turnlane calendar install --app out/TurnlaneCalendarHelper.app
turnlane calendar status                                   # 1行目が「Helper: 接続中 0.5.0 · 権限: フルアクセス」
```

- メモの本文はヘルパの外に出さない（会議リンクがある / ないの真偽値だけ）。同じ証明書なら TCC の許可は残る（D-053）

### 4. 確認項目（結果を PO に返す）

1. Turnlane で作った予定（または参加者のいない予定）をドラッグで動かす → ⌘Z で Calendar.app でも元の時刻に戻る。伸縮・
   パネルでの題名・カレンダーの変更も ⌘Z で戻る
2. 予定を動かした後、Calendar.app でその予定をさらに動かす → 1分ほど待って Turnlane で ⌘Z → 戻らずに
   「予定がカレンダー側で変わっていたため、元に戻しませんでした。」
3. 予定のパネルで「予定を削除」→ 確認のダイアログ。Esc でやめられる。⏎ で消える（日本語入力の変換確定の ⏎ では消えない）
4. 参加者のいる会議か、Meet / Zoom / Teams のリンクがある会議の5分前に、通知 `15:00 <題名> · 集中モードにしますか？` と
   ボタン「集中する」「しない」が出る（ボタンは通知にカーソルを載せると出る。通知のスタイルが「バナー」だとボタンは
   「オプション」の中）。「集中する」でメニューバーが月のアイコンになり、ポップオーバーの上と画面上部に
   `集中 · 16:00まで` と「終了」
5. 集中中に AI が許可待ち・自分の番になっても通知が出ない（メニューバーの件数は増える）。会議が終わったら
   `会議中に自分の番 N件（許可待ち M）` が1回だけ出る
6. 答えずに放っておく → 会議が始まっても集中しない。設定 > 通知 の「答えなければ自動で集中」をオンにすると始まった時刻から集中
7. メニューバーの右クリック → 集中モード → 30分 / 1時間 / 次の予定の終わりまで / 終了。⌘K でも同じ（「集中」「focus」で引ける）
8. Close the day の後（閉店モード）は会議の前に聞かない
9. 気になった点（聞くタイミング、対象にならなかった会議、出なかった通知）は、その予定の種類（参加者・リンクの場所）と
   `turnlane calendar status` の1行目を PO に返す
