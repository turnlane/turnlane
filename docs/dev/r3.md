# r3: 日報の AI 要約（M4-6）の確認手順

日報の AI 要約（オプトイン、既定オフ。D-041、ADR 0005 の追記、phase0-plan の「日報の AI 要約の仕様」）。

- 設定 > 日報の AI 要約 で オン にすると、送る内容（日報の Markdown だけ）と送り先（選んだツールの提供元）の説明が出る。「Turn on」（「オンにする」）で有効になる。オンの間も説明は出たまま
- シャットダウンの Step 2 を開くと、要約が無ければ作り始める（「Summarizing…」）。`Close the day` は待たない。届いたら Step 2 と日報の画面に出る（SSE `daily_note`）
- 失敗（CLI が無い・時間切れ・終了コード非0・空・長すぎ）は1行（`Summary unavailable — claude timed out · Retry`）。日報は要約なしで保存される
- 要約は `Edit` で直せる（空にして保存すると消える）。`Retry` で作り直す。勤務時間の `Edit` を保存すると作り直す
- `Copy Markdown`・`turnlane report`・MCP `get_daily_report` は先頭に `## Summary`（日本語は `## 要約`）と `(summary by claude)` を付ける
- 子プロセスは `<データディレクトリ>/summarize` で動かし、そのディレクトリは取り込みから常に除外する（設定画面の除外の一覧には出ない）。stdin は固定の指示文と日報の Markdown だけ（番兵テスト `test/privacy.test.ts` で確認）
- `turnlane doctor` に「日報の AI 要約: オン（claude: <パス>）」か「claude が見つかりません」を出す

自動で確かめているもの（`bun run check`）: 偽の `claude` / `codex`（シェルスクリプト）で、成功・Codex の `-o`・タイムアウト（SIGTERM を無視する CLI、stdout を握ったまま残る子プロセス）・終了コード非0・空・2,000 文字超・1MB の出力・見つからない・取り消し、`--help` によるフラグの確認、ログインシェルと既知の場所での検出、要約の作業ディレクトリのセッションが AI の作業にならないこと、API（生成・失敗・手での編集が後から届いた要約に上書きされないこと・Markdown の先頭の Summary・未来の日は 400）、マイグレーション 0006。

## ダミーデータで見る

dev-board は一時 HOME に置いた偽の `claude`（固定の文を返す）だけを使う。実際の `claude` / `codex` は探さず、呼ばない。

```sh
bun run build:web
bun scripts/dev-board.ts --summary --open '/shutdown?step=2'        # 4秒後に要約が届く
bun scripts/dev-board.ts --summary-fail --open '/shutdown?step=2'   # 上限10秒で時間切れ
bun scripts/dev-board.ts --summary-saved --open /daily-note          # 今日の要約を保存済みに
bun scripts/dev-board.ts --open /settings                            # 設定 > 日報の AI 要約
```

| ファイル（`docs/dev/screens/r3/`） | 見るところ |
|---|---|
| `shutdown-summary-running-*.png` | Step 2 を開いた直後。日報の上に Summary 欄と「Summarizing…」（「要約しています…」） |
| `shutdown-summary-*.png` | 届いた後。本文、小さく `summary by claude`、右上に `Edit` と `Retry` |
| `shutdown-summary-failed-*-dark.png` | 時間切れ。「Summary unavailable — claude timed out · Retry」。日報は普段どおり |
| `daily-note-summary-*-dark.png` | 日報の画面（閉じる前の今日）。Summary 欄と日報 |

## オーナーの入れ替え手順

```sh
cd ~/source/dayline
git pull               # main
bun install
bun run check
bun run build
bun run smoke
out/turnlane self-install    # デーモンを入れ替える（DB のマイグレーション 0006 が自動で当たる。適用前にバックアップを取る）
```

デスクトップアプリ（`Turnlane.app`）とカレンダーヘルパは入れ替え不要。

## 入れ替え後に実データで見る（結果を PO に返す）

1. 設定 > 日報の AI 要約 を オン → 説明を読んで「オンにする」。「<パス> を使います」に `claude` の絶対パスが出ること（出なければ「もう一度探す」。それでも出なければ `turnlane doctor` の1行を返す）
2. `turnlane config get report.ai_summary` に `"bin": "<claude のパス>"` が入っていること
3. 夕方にシャットダウン → Step 2 で「要約しています…」→ 1分ほどで2〜3文の要約が出ること。出る前に `Close the day` しても日報が保存され、後から要約が日報の画面に出ること
4. 要約の後、週ボードの AI レーン・`turnlane ai` に、要約の実行（`summarize` のディレクトリのセッション）が出ていないこと（U25 の確認。出ていたら版とその表示を返す）
5. `Copy Markdown` と `turnlane report` の先頭が `## 要約`（英語なら `## Summary`）で、末尾に `（claude による要約）` が付くこと
6. 試しに設定で時間の上限を 10 秒にして `Retry` → 「claude が時間内に終わりませんでした · やり直す」になること（確かめたら 90 秒に戻す）
