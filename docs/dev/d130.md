# D-130: カレンダーヘルパの許可の読み直し、カレンダーの知らせ、集中モードの入口（確認と入れ替えの手順）

- (1) カレンダーヘルパが許可の変化を見ない不具合: 常駐のヘルパが起動時の「未決定」をプロセスの中で覚えたまま、
  別のプロセス（`turnlane calendar authorize` が開いたヘルパ）で許可されても `no_access` を返し続けた。
  ヘルパ 0.7.0 は権限を 30 秒ごと・`storeChanged`・同期の `status` のたびに確かめ直し、変われば `EKEventStore` を
  作り直す。フルアクセスでないあいだは自分の実行ファイルを `--auth-status` で起動して別のプロセスで読み直し、
  食い違えば終了コード 75 で終わる（launchd の `KeepAlive` が起こし直す。起動から 60 秒未満なら起こし直さない）。
  `turnlane calendar authorize` も、フルアクセスになったら常駐のヘルパを `launchctl kickstart -k` で起こし直し、
  つながるのを待って同期を1回走らせる（phase0-plan 1.5）
- (2) カレンダーの知らせ: 権限が無い・ヘルパが2分以上つながっていない（一度つながったことがあるときだけ）・同期の
  失敗が15分続くとき、サイドバーの下（取り込みの知らせの下）に「カレンダーの予定を取れていません」。押すと設定 >
  カレンダー、ホバーで理由。畳んだサイドバーは設定のアイコンに印（ux-mvp 3章、m2-api 25章の `calendarHelper.problem`）
- (3) 集中モードの入口: メニューバーのポップオーバーの「集中する ▸」（30分 / 1時間 / 次の予定の終わりまで）と集中中の
  「終了」。予定の詳細パネルと予定の右クリックの「この予定の間は集中する」（ux-mvp 4.15、m2-api 25章）

自動で確かめられる部分は `bun run check`（判定・API・知らせ・authorize の起こし直し）、`bun run check:helper`
（`--fake-auth-file` で古い権限を再現し、起こし直してから同期できること）、`swift test --package-path native/calendar-helper`
（権限の読み方を差し替えた再現テスト）、`bun run e2e`（`actions` スイートの予定の右クリック・詳細パネル・メニューバーの集中）。

bun run build:web

## オーナーの手順

### 1. デーモンと UI の入れ替え（必要。マイグレーションなし）

```sh
cd ~/source/dayline
git pull               # main
bun install
bun run check
bun run build
bun run smoke
out/turnlane self-install    # デーモンを入れ替える
```

- 予約は `focus.state`（setting）に足すだけで、DB のマイグレーションは無い
- メニューバーのポップオーバーは web の `/tray` なので、デスクトップアプリの作り直しは要らない（デーモンの入れ替えで変わる）

### 2. カレンダーヘルパの入れ替え（→ 0.7.0。必要。許可の読み直し）

```sh
TURNLANE_CODESIGN_IDENTITY="Apple Development: <名前> (<ID>)" bun run build:helper
bun scripts/check-calendar-helper.ts --skip-build   # 任意（一時 HOME。EventKit には触れない）
turnlane calendar install --app out/TurnlaneCalendarHelper.app
turnlane calendar status                            # 1行目が「Helper: 接続中 0.7.0 · 権限: フルアクセス」
```

- 同じ証明書で署名すれば TCC の許可は残る（ad-hoc 署名だと外れることがある。D-053）。外れたら `turnlane calendar authorize`
  （0.7.0 の CLI は最後に常駐のヘルパを起こし直して同期する）

### 3. 確認項目（結果を PO に返す）

1. `turnlane calendar status` が接続中・フルアクセスで、予定が出る
2. （任意・再現の確認）システム設定 > プライバシーとセキュリティ > カレンダー で TurnlaneCalendarHelper を一度外す →
   サイドバーの下に「カレンダーの予定を取れていません」（すぐ。ヘルパが終了させられて未接続なら2分後）→
   `turnlane calendar authorize` で許可 → 最後に「常駐のヘルパを起動し直しました」「同期しました」と出て、知らせが消える
3. メニューバーのアイコンを左クリック → 下の「集中する ▸」→ 30分 → その行が `集中 · HH:MMまで` と「終了」になる → 終了で戻る
4. これからの予定を右クリック →「この予定の間は集中する」→ もう一度右クリックすると ✓。予定の詳細パネルにも同じ
   ボタンがあり、押すと取り消す。設定した会議は5分前に聞かれず、開始の時刻に集中モードになり、終わりで戻る
5. 進行中の予定で「この予定の間は集中する」→ すぐ集中モードになる
