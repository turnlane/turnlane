# M3-3 カレンダーへの書き戻しの確認手順

> **D-093（2026-10-07）で置き換え**: タスクの時間ブロックの書き戻しはやめた。予定を Turnlane から作成・編集する方式と、
> これまで書いた時間ブロックの予定の削除は [d093.md](d093.md)。以下は当時の記録。

週ボード・デイビューで置いた時間ブロックを Mac のカレンダーへ書き、スマホのカレンダーにも出す（ADR 0003 とその追記、
phase0-plan 4.5 の「M3-3 の方式」）。**書き先の既定は Calendar.app の「新規イベントのデフォルトカレンダー」**で、準備は要らない
（D-072。Calendar.app で予定を作ったときと同じカレンダー・同じアカウントに入る）。設定で専用の `Turnlane` などを選ぶこともできる。自動で確かめられる部分は `bun run check`（偽のカレンダーで書き戻し・同期・Calendar.app 側の変更の取り込み）と
`bun run check:helper`（ヘルパを `--fake-store` で動かし、デフォルトカレンダーへの `upsertEvent`（`calendarId` なし）・同じ予定の更新・`deleteEvent` が WebSocket 越しに通ること。EventKit には触れない）が行う。
実カレンダーへの書き込みは下のオーナーの手順で確かめる。

- 書くもの: 時間ブロック（題名 = タスクの題名、開始・終了、`url = dayline://timeblock/<id>`）。場所・メモ・参加者は書かない。既存の予定は書き換えない（ヘルパは目印の付いた自分の予定しか更新・削除しない。デフォルトカレンダーの他の予定には触れない）
- 書き先: 既定は Calendar.app のデフォルトカレンダー（書くたびにヘルパが解決する。Calendar.app でデフォルトを変えたら、以後の新しい予定はそちらへ）。既に書いた予定は、デフォルトが変わっても元のカレンダーのまま更新する（移さない。Calendar.app と同じ）
- 書くタイミング: ブロックを作る・動かす・伸ばす・外す（`⌫`）、タスクの題名を変える・削除する・復元すると、1秒以内に書く。ヘルパが止まっている間は「書き込み待ち」で残り、つながったら書く。失敗は 1・2・4… 分後（最大 60 分ごと）に再試行
- 読み取り側: Turnlane が書いた予定は、デフォルトカレンダーのような他の予定と同じカレンダーにあっても目印で見分け、週ボード・デイビューに予定として出ない。空き時間・放置・日報の会議時間にも数えない（時間ブロックとして1回だけ数える）。同じカレンダーの他の予定は今までどおり出る
- Calendar.app（やスマホ）で Turnlane が書いた予定を動かす・伸ばすと、次の同期（変更通知か5分ごと）で時間ブロックも動く。消すと時間ブロックが外れる（タスクは残る）。題名の変更は取り込まない
- 書き戻しを使い始めた時点（デーモンとヘルパの入れ替えで書けるようになった時点、書き先を変えた・オフから戻した時点）では、終わりが今より後の時間ブロックだけを書く。それより前に終わったブロックは書かない（パネルに「カレンダーに書いていません（書き戻しを始める前のブロック）」。D-073）。使い始めた後に置いた・動かしたブロックは、過去の時刻でも書く

## オーナーの手順

### 1. デーモンと UI の入れ替え

```sh
cd ~/source/dayline
git pull               # main
bun install
bun run check
bun run build
bun run smoke
out/turnlane self-install    # デーモンを入れ替える（D-072・D-073 では DB のマイグレーションは無い）
```

デスクトップアプリ（`Turnlane.app`）は入れ替え不要（UI はデーモンが配信する）。

書き先を選んでいなかった場合、入れ替えたデーモンはヘルパが 0.3.0 になった時点で既定（Calendar.app のデフォルトカレンダー）への書き戻しを始める。
そのとき書くのは終わりがその時点より後の時間ブロックだけで、過去のブロックはまとめて書かない（D-073）。事前に書き戻しをオフにする必要は無い。

### 2. カレンダーヘルパの入れ替え（→ 0.3.0。D-072 で必要）

書き戻しはヘルパ 0.2.0 から、既定（Calendar.app のデフォルトカレンダー）への書き戻しは 0.3.0 からの機能。S1 と同じ証明書で署名し直す（同じ証明書なら TCC の許可はそのまま残る。D-053）。

```sh
security find-identity -v -p codesigning          # S1 で使った「Apple Development: …」を確かめる
TURNLANE_CODESIGN_IDENTITY="Apple Development: <名前> (<ID>)" bun run build:helper
bun scripts/check-calendar-helper.ts --skip-build # 任意（上でビルドした .app を一時 HOME で確かめる。EventKit には触れない）
turnlane calendar install --app out/TurnlaneCalendarHelper.app
turnlane calendar status
```

- `turnlane calendar status` の1行目が `Helper: 接続中 0.3.0 · 権限: フルアクセス` になること
- 権限が「未決定」「拒否」に戻っていたら `turnlane calendar authorize`（ダイアログ）か、システム設定 > プライバシーとセキュリティ > カレンダー で TurnlaneCalendarHelper を「フルアクセス」に
- 古いヘルパのままだと、書き戻しは「失敗（helper_outdated）」になり、`turnlane calendar status` と設定画面に「ヘルパが古い」と出る（他の機能は動く。0.2.0 のままでも、専用カレンダーを選べばそこへは書ける）
- デーモンを先に入れ替えてヘルパが 0.2.0 のままの間は、既定の書き戻しが helper_outdated で止まる（1・2・4… 分ごとに再試行）。ヘルパを入れ替えると次の再試行で書く。このとき書くのは終わりが今より後のブロックだけ（D-073。0.2.0 の間に失敗になっていた過去のブロックは書かずに「書き戻しを始める前のブロック」になる）

### 3. 書き先を確かめる（準備は不要）

1. Calendar.app の 設定 > 一般 > 「デフォルトカレンダー」が、時間ブロックを入れたいカレンダー（スマホに出したいなら Google アカウントのカレンダー）になっていることを確かめる。ここで選んだカレンダーに入る
2. `turnlane calendar status` に `Writeback: Calendar.app のデフォルト → <カレンダー名>（<アカウント>） · 反映待ち 0 · エラー 0` と出れば準備完了。設定 > カレンダー では「Write time blocks to: Calendar.app default」「Now: <カレンダー名>」
3. 以前に専用の `Turnlane` を書き先に選んでいた場合は、そのまま Turnlane に書き続ける（`Writeback: Turnlane（…）`）。Calendar.app と同じ挙動にするなら、設定 > カレンダー の「Write time blocks to」で「Calendar.app default」を選ぶか `turnlane calendar writeback default`。既に Turnlane に書いた予定は Turnlane に残ったまま更新される（移さない）

### 4. 確認項目（結果を PO に返す）

1. 週ボードでタスクを今日の時間軸へドラッグする → 1分以内に Calendar.app のデフォルトカレンダーに同じ題名・時刻で出る。数分以内にスマホのカレンダーにも出る
2. 週ボードでそのブロックを別の時刻へ動かす・下端で伸ばす → Calendar.app とスマホで動く・伸びる（予定は増えない）
3. タスクのパネル（クリック）で題名を変える → 予定の題名も変わる
4. `⌫` でブロックを外す → Calendar.app とスマホから消える。タスクは Unscheduled に残る
5. Calendar.app で Turnlane が書いた予定をドラッグして動かす → 1分ほどで週ボードのブロックも動く。Calendar.app で消す → ブロックが外れる（タスクは残る）
6. 週ボード・デイビューの予定のレーンに Turnlane が書いた予定が重ねて出ないこと（同じカレンダーの他の予定は出ること）、今日のヘッダの Free・Events がブロックを置いた分だけ二重に減っていないこと
7. タスクのパネルの「Calendar」が「In your calendar」になること（書く前は「Waiting to write」）
8. `turnlane calendar status` の Writeback の行が「反映待ち 0 · エラー 0」に戻ること。エラーが残る場合はコード（`no_default_calendar`・`not_writable`・`save_failed` など）を PO に返す
9. （D-072）Calendar.app の 設定 > 一般 でデフォルトカレンダーを別のカレンダーに変え、新しいブロックを置く → 新しいデフォルトに入る。前に書いた予定のブロックを動かす → 元のカレンダーのまま動く（移らない）。設定画面の「Now:」も1分ほどで新しいカレンダー名になる
10. （D-072）スマホの Google カレンダーで、Turnlane が書いた予定の「URL」が消えずに残っているか（予定の詳細）を見て PO に返す。URL は Turnlane の予定の目印で、消えると見分けが書いたときの ID だけに頼ることになる
11. （D-073）入れ替えの後、Calendar.app のデフォルトカレンダーに、今日のうち既に終わった時間ブロックや前日以前のブロックが作られていないこと。そのブロックのパネルの「Calendar」が「カレンダーに書いていません（書き戻しを始める前のブロック）」になっていること。今より後のブロックは書かれていること
12. （D-073）そのような過去のブロックの1つを週ボードで少し動かす → 書かれる（使い始めた後の操作なので）。不要なら `⌫` で外すと予定も消える

### 書き戻しをやめるとき

設定 > カレンダー の「Write time blocks to」で「Off」を選ぶ（`turnlane calendar writeback off`）。以後は書かない。
既に書いた予定はそのカレンダーに残る。要らなければ Calendar.app で消す（消した予定のブロックは外れる。タスクは残る）。オフの間は照合もしないので、オフにしてから消すとブロックはそのまま残る。

### 予定のパネルの「カレンダーで開く」（D-070）

予定をクリックして出るパネルの「Open in Calendar」は、初回だけ macOS が「turnlaned が Calendar を制御しようとしています」と許可を聞く。
許可するとその予定を Calendar.app で開く。許可しない・見つからないときは Calendar.app を開くだけ（システム設定 > プライバシーとセキュリティ > オートメーション で後から変えられる）。
