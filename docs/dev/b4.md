# 段階 B (4): 朝の計画（M4-1・M4-7）の確認手順

- 仕様: ux-mvp 8章（朝の計画）、m2-api 16章（`GET /api/rituals/morning`、`POST /api/rituals/morning/complete`、移動候補）、確定デザイン `docs/design/screens/morning-plan-v1.png` と調整点 M1〜M3
- 画面は `/morning`（サイドバーなし・中央 760px。シャットダウンと同じ儀式レイアウト）
- 入口: その日初めて開いたときの上部の帯 `Plan the day ⏎ · Skip`（設定 → Plan the day prompt でオフ）、サイドバーの `Plan the day`（その日まだ終えていなければ点）。⌘K の `Plan the day`（段階 B (5)。docs/dev/b5.md）
- `Start the day ⌘⏎` で `daily_note.morning_done_at` と `usage_event` の `ritual_morning` を記録する（`turnlane stats` の14日カウントの「朝」）

## ダミーデータで見る

```sh
bun run build:web
bun scripts/dev-board.ts --morning --lang en --theme dark   # --lang ja
```

`--morning` は今を 8:40 にし（`--now` で変えられる）、昨日 19:40 に閉じた状態にする。夜のあいだに AI が動いた結果（自分の番3件・エラー1件・完了3件）、持ち越し（`Tax return documents ↺ 3`、昨日の日付のまま残った2件）、計画が空き（10:00〜19:00 − 予定 1h45m = 7h15m）を 1h30m 超える今日を作る。夜の実行は、夕方に人が頼んだセッションがタスク通知で動き直したものとして書く（夜のターンは勤務の操作に数えないので、待ちは時間外に始まる）。

Playwright で次を通した（API の結果で確かめた）: 帯が出る → 何も選んでいない週ボードで `⏎` → `/morning`。Step 1 で `t`（今日へ）・`m`（次の稼働日へ。スヌーズ）・`e`（対応不要）。`⌘⏎` で Step 2、`t` で `Tax return documents` の持ち越し回数が 3 → 4、`⌫` で `Draft newsletter` が canceled。`⌘⏎` で Step 3、`↓ ⏎` で `Write article outline` が 10/5 へ。`⌘⏎`（Start the day）で週ボードへ戻り、帯が消え、`/api/stats` の今日が `morning: true, counted: true`。

## 確定デザインとの差

- 画像の失敗した定期実行（Cowork）は Phase 0 の範囲外（M3）。ダミーデータは Claude Code の API エラーで、2行目は `AI 2m · ran 6:58–7:00`（画像の `api_error` のようなエラーの種類は保存していないので出さない）
- 画像の Step 3 の左の時間軸は `Usual end 16:15` だが、計画上の勤務時間（D-062）で描く（勤務時間外の灰色）
- 画像は Step 1 の判断する行に ⏎ の開くボタンが無い。フッタの `⏎ open` だけにした（画像に合わせた）
- 画像の題名「Answer: migration order question」は AI 項目の題名から作る自動の題名（`Reply: …`）になる

## 入れ替え後に実データで見る

- 朝、その日初めて開いたときに帯が出て、`Skip` を押すとその日は出ないこと。設定 → Plan the day prompt をオフにすると出ないこと
- 前の日に Close the day した後、夜に動いた AI の自分の番・エラーだけが Step 1 に出ること。閉じずに終えた日は `Since you stopped working at …` になること
- Start the day の後 `turnlane stats` の今日の `morning` に印が付くこと
