# D-076・D-077: 確認手順

## D-076: 3日ボードの左の列

仕様は ux-mvp.md 4.4.0、m2-api.md 20章。

- 左の列 = 「前の稼働日」と「実際に作業した直近の日（基準日より前で `work_day_auto` に行がある日）」のうち新しい方。`work_day_auto` は勤務時間（D-018）と同じ操作（AI への人間入力・Turnlane の操作 `user_op`・手動のタスク完了）から作るので、AI の定期実行だけの日は入らない
- 今日（基準日）は稼働日でなくても真ん中。右は次の稼働日のまま
- `[` / `]` は表示中の左・右の列の日へ移る（左が作業した休日ならその日が次の基準日）

自動で確かめているもの: `packages/core/test/date/workdays.test.ts` の `boardPrevDay`（月曜に日曜の作業あり → 日曜、なし → 金曜、祝日明け、基準日以降の作業は数えない）、`apps/daemon/test/board-api.test.ts` の D-076。

## D-077: ショートカットの一覧と変更

仕様は ux-mvp.md 6章・6.2、m2-api.md 21章、desktop-shell.md 2.5・5章。

- キーの定義は `apps/web/src/keys/keymap.ts` の1か所（単打・2打鍵・⌘ 系・⌘K の中・儀式・クイック入力のホットキー）。説明は i18n の `keys.*`（日英）
- 設定 > キーボード（`/settings#keyboard`。`?` の一覧の下のリンクからも開く）: カテゴリ別の一覧と検索、`＋` でキーを押して記録、`×` で外す、既定に戻す、すべて既定に戻す。衝突は行の下に赤で出し、衝突がある間は保存できない
- 保存先: アプリ内のキーは `ui.keybindings`（端末ごと）、クイック入力は `desktop.quick_add_shortcut`（従来の「Desktop app」の行から移した）
- 反映: `?` の一覧、⌘K の行、上部の `3日 / 週 / 日` のツールチップと `⌘K`、儀式のフッタ、他の開き方のメニューの返答タスクのキー、デスクトップアプリの表示メニュー（`⌘` 付きの1打鍵だけ。無ければメニューにキーを出さない）

## オーナーの入れ替え手順

```sh
cd ~/source/dayline
git pull               # main
bun install
bun run check
bun run build
bun run smoke
bun run build:desktop  # 表示メニューのキーを設定から付け直す（Rust の変更）。署名は docs/dev/desktop.md の 1 章
out/turnlane self-install    # デーモンと turnlane を入れ替え、out/Turnlane.app も ~/Applications に置き直す（マイグレーションは無し）
```

Web とデーモンの変更（左の列、キーボードの節、上書きの反映）はデーモンの入れ替えと開いているウインドウの再読み込み（⌘R）で反映される。デスクトップアプリを入れ替えない間は、表示メニューは既定の ⌘1〜⌘3 のまま（3日 / 週 / 日のキーを変えても、メニューのキーが先に取る）。クイック入力のホットキーの変更は今のアプリでも効く（従来と同じ設定を読む）。カレンダーヘルパは入れ替え不要。
