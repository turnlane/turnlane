# ADR 0022: 図つきの問い（MCP の ask_user）: 答えをツールの結果で AI に戻す。中身はデーモンのメモリにだけ持つ

- ステータス: Accepted（2026-11-16。2026-11-19 追記あり。末尾）
- 日付: 2026-11-16
- Amends: [ADR 0021](0021-report-from-own-scripts-and-agents.md) の Decision 6（この口に限る）

## Context

- AI が人の判断を仰ぐとき、今は端末の文の問い（または AskUserQuestion の選択肢）で聞く。案の違いが見た目や構成にあると、文だけでは比べにくく、人は端末に戻って長い文を読むことになる。
- Turnlane から答える（ADR 0019）は答えを端末のタブに文字として届ける。端末を持たないアプリ（Claude Agent SDK の上のアプリ。T3 Code など）や送る口の無い端末には届かない。報告（ADR 0021）は「答えを報告した側へ戻す中継は作らない」とした（Decision 6）。
- AI のツールの呼び出しは、結果が返るまで待つ。MCP のツールが人の答えを待って返せば、端末への文字送りなしに答えが AI に戻る。Claude Code は MCP の呼び出しを約 28 時間待つ。ただし stdio の呼び出しで応答も進捗の通知も無いまま 30 分たつと打ち切り、進捗の通知は活動に数える。2 分を過ぎた呼び出しはバックグラウンドの作業に回り、そのまま待つ。Codex の MCP のツールの既定の上限は 60 秒（`mcp_servers.<id>.tool_timeout_sec`）。
- 問いと図は会話の中身にあたる。ADR 0005 は会話の本文を保存も送信もしない。ADR 0018 の限定した保存の対象にも入れない。

## Decision

1. **MCP のツール `ask_user`**: AI が問い（120 文字まで）・背景（任意、600 文字まで）・案（2〜4 個。`label`・`description`・任意の `recommended`・任意の `figure_path`）・任意の説明のページ（`explain_path`）を渡す。1 回の呼び出しに問いは 1 つ。Turnlane はその作業のカードを回答待ちにして自分の番に出し、人が選んだ案とメモを**ツールの結果として AI に戻す**: `{ choice, note? }`、メモだけなら `{ note }`、閉じたら `{ dismissed: true }`。ADR 0021 の Decision 6（答えを報告した側へ戻す中継は作らない）は、この口に限って改める。報告（`report_ai_work`・`turnlane ai report`・`POST /api/ai/reports`）の答えは今までどおり読めるだけ。
2. **中身はデーモンのメモリにだけ**: 問い・背景・案・図・答えは、問いが開いている間だけデーモンのメモリ（`apps/daemon/src/ask/`）に持つ。DB・spool・ログ・SSE・書き出し・バックアップには入れない（ADR 0005 のまま）。DB に残すのは「回答待ちだった」という返答タスクの行（種類 `reply`、`artifact_ref` が `ask_user:<問いの ID>:ask`、開いた時刻と閉じた時刻・理由）だけ。答えは MCP のプロセスが受け取ったら捨てる（受け取られなければ 1 分で捨てる）。閉じた問いは中身を捨て、状態と時刻だけの控えを 1 時間残す。記録（トランスクリプト）には AI の呼び出しの入力として問いが残るが、Turnlane はそれを待ちの中身として保存しない（ADR 0018 の待ちの中身の保存から外す）。番兵のテストがデータディレクトリの全ファイル・全テーブル・SSE・ログに中身が無いことを確かめる。
3. **デーモンが再起動すると問いは消える**: 開いていた問いは失われ、返答タスクは `auto:ask_lost` で閉じる。待っている `ask_user` の呼び出しは「端末で聞き直してください」というエラーを返す（結果の long-poll が 404）。AI はそれで端末で聞き直す。
4. **図は静的な HTML / SVG / CSS だけ**: 図のファイル（1 つ 200 KB まで）は MCP のプロセス（AI と同じ権限）が読み、中身をデーモンに送る。デーモンに手元のパスを読む口は作らない。web は図を `<iframe sandbox>`（`allow-scripts`・`allow-same-origin` を付けない）に `srcdoc` で入れ、先頭に CSP の meta（`default-src 'none'; style-src 'unsafe-inline'; img-src data:`）を入れる。枠の中のスクリプトは動かず、枠の中からは何も外に出られない（念のため、外を指す URL の属性・script・meta の http-equiv なども取り除く）。Turnlane の色と文字を CSS 変数（`--tl-*`）で渡し、明暗どちらでも読めるようにする。アプリ全体の CSP はこの決定では足さない。読めない・大きすぎる図は「図を読めませんでした」の 1 行にし、案は選べる。
5. **カードの決め方**: (1) MCP のプロセスの親（AI のプロセス）が動いているセッション（`ai_session.live_pid`）のカード、(2) 無ければ MCP のプロセスの作業ディレクトリ（その下を含む）で最近 24 時間に動いたターンのカード（リポジトリ × ブランチ。既定ブランチはセッションのカード）、(3) どちらも無ければ自分のカード（報告の作業。出どころ `agent`、題名は作業ディレクトリの名前。ADR 0021 の道を通り、spool に書くのは状態と題名だけ。問いが閉じたら `done`）。AI の取り込みがオフでカードにできなければ、問いは開かずにエラー（端末で聞く）。
6. **カードの状態**: 問いが開いている間、カードは回答待ち（`needs_input`、理由 `ask_user`。エラーだけが先）で、回答待ちの返答タスクをすぐ作る（返答タスクの設定・プログラム経由のセッションによらない。通知は今の回答待ちと同じ）。AI のセッションの記録には結果の無いツールの呼び出しが残り、Claude Code はバックグラウンドに回して待つので、セッションだけを見ると実行中・止まった・終わったに見える。問いが開いている間はそれより問いを優先し、同じカードに問いで終わったターンの返答タスクを重ねず、端末で答える待ち（Turnlane から答える）も出さない。返した・閉じた・AI 側で打ち切られた・消えたで返答タスクが閉じ（`auto:answered`・`dismissed`・`auto:ask_cancelled`・`auto:ask_lost`）、回答待ちから外れる。自分の番の「対応不要」「完了」は問いを閉じる（AI には `dismissed`）。
7. **長い待ち**: MCP のプロセスはメッセージを並行に処理する（待っている間もほかのツールに答える）。答えは long-poll（1 回 25 秒）で待ち、デーモンに届かない間は 60 秒まで再接続する。クライアントが `progressToken` を付けていれば 60 秒ごとに進捗の通知を送る。`notifications/cancelled` と入力の終わり（AI が終わった）は問いを取り消す（画面は「もう進んでいます」）。デーモンは 90 秒待ちに来ない問いを取り消す（MCP のプロセスが居なくなった）。
8. **対象**: 最初の版は Claude Code（Claude Agent SDK の上のアプリを含む）を対象にする。Codex は README に `tool_timeout_sec` の延ばし方を書くだけで、特別な方式は作らない。ローカルだけで動き、iPhone・同期は扱わない。
9. **AI への指示**: Claude Code のスキル（`skills/turnlane-ask/SKILL.md`）と、CLAUDE.md / AGENTS.md に貼る 1 節を配る。`turnlane skill install|uninstall` が Turnlane の印の付いたものだけを足し・外す（hooks と同じく冪等で、Markdown は書き換える前にバックアップを取る）。入れた人の AI にだけ効く。

## Consequences

- 端末に送る口の無いアプリ・端末でも、AI の判断の問いに Turnlane から答えられる。答えは端末の入力ではなくツールの結果なので、届いたかを確かめる手間が無い。
- 中身はメモリにしか無いので、デーモンを再起動すると開いていた問いは消える。AI は端末で聞き直す。後から「何を聞かれて何と答えたか」は Turnlane には残らない（返答タスクの時刻だけ）。
- 図は AI の書いた静的なものに限る。動きのある図・外の画像は出せない。
- Codex は既定の 60 秒を超えると呼び出しが打ち切られる（利用者が設定を延ばすまで使いにくい）。
- 2 列の画面（左に問いと案、右に説明）は詳細パネルが広いとき（節の幅 520px 以上）だけ。狭いと説明は下に回る。

## 追記（2026-11-19）: AI が ask_user を使う条件

実際の利用で、AI は ask_user を呼ばず、組み込みの AskUserQuestion や文の問いでターンを終えていた。スキル・節の条件（「具体的な案から選んでもらうとき、端末で聞く代わりに」）が弱く、MCP のツールの形を後から読み込むホストでは、AI が常に見るのはスキルの 1 行の description と CLAUDE.md の節だけだった。Decision 9 の指示の条件を次に決める（PO 決定）。

1. **条件**: 人に決めてもらう・確かめてもらう問いで、文だけでなく図で説明できるもの（画面の配置、構成・アーキテクチャ、流れ・順序、変更の前後、数字の並び）は、**必ず** ask_user で聞く。組み込みの AskUserQuestion と、文の問いでターンを終えることの代わりにする。案（2〜4）の無い説明には使わない。文だけで足りること（はい・いいえ、名前、パス）は今までどおり聞く。ask_user が失敗する・使えないときは端末で聞く（変わらない）。
2. **書く場所**: スキルの description（AI が常に見る行なので、これだけで条件が伝わるようにする）、スキルの本文の冒頭、CLAUDE.md / AGENTS.md の節、MCP の ask_user のツールの説明。文は同じ条件にそろえる（`packages/core/src/ask-skill.ts`・`apps/cli/src/commands/mcp-ask.ts`）。
3. **CLAUDE.md の節を標準の手順にする**: スキルだけでは使われないことが多いので、`turnlane skill install` の出力と README は `--claude-md <ファイル>` で節を入れることを標準として案内する。
4. **入れ直し**: 文が変わると、`turnlane skill status` はスキルと節を `outdated` と出す（節も中身を今の文と比べる。節が 2 つ以上あっても `outdated`）。`turnlane skill install`（`--claude-md` / `--agents-md` を付けて）はその場で置き換え、節を重ねない（2 つ以上あれば 1 つにまとめる）。
