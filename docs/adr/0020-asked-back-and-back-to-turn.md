# ADR 0020: 問い返しは閉じずに待つ。閉じた行は手で自分の番に戻せる

- ステータス: Accepted（Issue #3。2026-10-30）
- 日付: 2026-10-30

## Context

- AI の問い（返答タスク）に、利用者が答えではなく問いで返すことがある（「どうやって見るの？」「違いを教えて」）。今までは同じセッションの人の入力をすべて返答とみなし、返答タスクを `done`・`auto:human_input` で閉じていた。AI がその問いに答え終わると、元の問いは自分の番から消えたまま残り、答えるべきことを見失う。
- 閉じた行（返答・解決（推定）・対応不要・期限切れ・置き換え）を利用者が「まだ終わっていない」と思っても、戻す手段が無かった（`y` は返答タスクを新しく作るだけで、自動で閉じた行や問い返しには効かない）。
- 入力の本文は保存しない（ADR 0018 の 1）。保存しているのは自分の指示の 1 行目（伏せ字の後、120 文字まで）だけ。

## Decision

1. **問い返しの判定は保存した 1 行目で行う**: 開いている返答タスク A の問いの後、同じセッションの人の入力の 1 行目（`ai_instruction.text`）が問いの形なら問い返しとみなす（collectors の `asksBack`）。問いの形は、`?`・`？` で終わる、「教えて・知りたい・とは・って何・どうやって・なぜ・どこ・どれ・分からない」など、英語の `how do I / what is / why / where / which / is it …` など。依頼（「直してもらえますか？」「can you …?」「please …」）は `?` で終わっても問い返しにしない。保存していない入力（設定 `turn.store_detail` がオフ、短い返事、スラッシュコマンド）は今までどおり返答とみなす。本文は新たに保存しない。
2. **問い返しは A を閉じない**: 問い返しの入力は A を閉じる返答に数えない。A は DB では `open` のまま、その入力で始まったターンが動いている間は、読み取りの時点で `asked_back`（問い返し中）にする（`GET /api/queue` の follow-up の `status`、`GET /api/work-items/:id` の `followUps[].status`）。`asked_back` は帯・件数・通知・「後で」に出さない（`visibleQueue` は `open` だけ）。DB に新しい状態は足さない（`scheduled` と同じく読み取りの時刻で決める）。
3. **戻すか、置き換えるか**: 問い返しのターンが終わったとき、
   - AI の答えが問いでなければ（途中で止めた・エラー・Stop の hook で記録に終わりが無いまま終わったものも含む）、A は元の件名・元のトリガのまま自分の番に戻る（`open` のまま。時間での自動の戻しは入れない。返答が来るまで待つ）。
   - AI の答えが新しい問い（締めの問い「ほかにありますか？」は除く）なら、A を `superseded`・`auto:asked_back_replaced` で閉じ、新しい問いの返答タスクがそれを置き換える（新しい返答タスクは今までどおり猶予の後に作る）。
   - 次の問いの形でない入力が来れば、今までどおり A を `done`・`auto:human_input` で閉じる（時刻はその入力の始まり）。
4. **手で自分の番に戻す**: `POST /api/work-items/:id/back-to-turn { followUpId? }`。対象の行を `open` にし、`closed_at`・`close_reason`・スヌーズを外し、`follow_up.returned_at` に今を入れる（マイグレーション 0021）。閉じたときに一緒に完了にしたタスクは未完了に戻す（`reopen` と同じ）。`followUpId` を省けば、カードの問い返し中の行 → 最後に閉じた行 → どちらも無ければ返答タスクを作る（`y` と同じ）。戻した行は、手で閉じるか、戻した後にそのカードで新しいターン（新しい記録）が始まって `done`・`auto:new_record` で閉じるまで残る。人の入力・PR の変化・状態の変化・期限（72 時間）では閉じない。戻した行は問い返しの判定もしない。
5. **見せ方は増やさない**: 流れ（「この項目の流れ」）の稼働の行の補足を、問い返した稼働だけ「頼んだ: …」から「問い返し: …」に替える。新しい色・状態の名前は足さない。戻す操作は、キー `u`（`y` 返答タスク・`a` 答える・`p` 時間に置く などと衝突しない。`b` は「いつかへ」に取ってある）、流れの閉じた行（閉じた後の区間・期限切れ・問い返した稼働・完了の印）と自分の番の画面の「今日閉じた」行のホバーのボタンと右クリック、AI カードの右クリック、AI 詳細パネルの `⋯` に置く。
6. **パーサの版は上げない**: 判定は取り込みではなく判定の時点（derive）で、保存済みの `ai_instruction` から行う。過去の記録を読み直さなくても、保存済みの 1 行目にそのまま効く。

## Consequences

- 問い返しの間、A は自分の番からも「後で」からも消え、AI の答えが終わると戻る。通知は戻ったときに改めては出さない（A は開いたままなので、まとめの通知の扱いは今までと同じ）。
- 判定は文の形だけを見るので、問いの形の答え（「1 でいい？」）は問い返しとみなす。その場合も、AI の答えの後に A が戻るだけで、失うものは無い。逆に問いの形でない問い返し（「違いがよく見えない」）は今までどおり A を閉じる。そのときは `u` で戻せる。
- `store_detail` がオフの利用者には問い返しの判定が効かない（`u` は効く）。
- 戻した行の放置の数え方は今までの待ちの区間のまま（戻した時刻からの区間は作り直さない）。
