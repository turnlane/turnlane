# ADR 0015: 本体に拡張点を持たせ、公式の配布物には別ライセンスの追加（拡張）を組み込めるようにする

- ステータス: Accepted
- 日付: 2026-10-08
- 関係: Amends [ADR 0008](./0008-mit-no-server-open-source.md)（決定 2 のうち「ライセンスキーの確認」の行と、決定 5 の「拡張はプラグインではなくリポジトリへの PR で受ける」）。PO 決定 D-108・D-110 (6)(7)。リポジトリの CLAUDE.md の原則 11、[design-system.md](../design/design-system.md) の「価格・アップグレードの UI を出さない」の規則も、この ADR に合わせて言い直す

## Context

- 本体（このリポジトリ）は MIT で公開し、作者が運用するサーバーを持たない（ADR 0008）。この約束は変えない。
- 公式の配布物（作者が署名・公証して配る `.app`）にだけ、別のライセンスで配る追加の機能を組み込みたい（D-108）。追加の機能のコードは公開しない。MIT のコードの中に有料の判定を置いても、フォークで外せるので意味がない。
- 追加の機能は、朝の計画の手順・設定の節・タスクのメニューなどの画面と、デーモンのタイマー・テーブル・API の両方に入る。今の本体は、設定のキー・設定の節・マイグレーション・ルート・パレット・辞書が閉じた一覧になっていて、外から足せない。
- 実行時に読み込むプラグイン（ディスク上の JS を `import()` する）は、署名・公証の対象外で、改ざんの検証・版の互換・読み込みの安全を自前で作る必要がある。外部の人にプラグインを書いてもらう予定もない。

## Decision

1. **拡張点を持つ**。本体は「拡張（extension）」という一般の仕組みを持ち、ビルドのときに拡張を組み込める。拡張の型・一覧・つなぎ方は本体（MIT）に置き、拡張の中身は本体に置かない。
   - デーモン: 設定のキー（`ext.<id>.` の接頭辞）、マイグレーション（テーブル名は `ext_<id>_` の接頭辞。本体の連番とは別に `__ext_migrations` で管理）、HTTP のルート（`/api/ext/<id>/*` の下だけ）、`start` / `stop`（タイマー等）。本体の部品（起動・在席・カレンダー・通知の保留・確認支援・AI の1回の実行・スリープさせない、など）を `ExtDeps` として渡す。
   - Web: 画面の経路、設定の節、朝の計画の手順、タスクのメニュー、タスクの詳細パネルの節、コマンドパレットのコマンド、辞書、AI に頼むの入力の行。
   - 組み込みはビルドのときだけ（`scripts/build.ts --ext <dir>`、Web は Vite の alias）。拡張を指定しないビルド（公開のソースからのビルド、CI）では一覧が空で、今までと同じ動作になる。拡張は `EXT_API_VERSION` で本体との版を合わせる。
   - ADR 0008 の決定 5 のうち、取り込みアダプタと外部サービスの連携の方針（PR で受ける、外部側からローカルの MCP / CLI を呼んでもらう）は変えない。この ADR が足すのは「ビルドのときに組み込む拡張」だけで、実行時に読み込むプラグインは作らない。
2. **公式の配布物には別ライセンスの拡張が入りうる**。公式の配布物は、本体（MIT）と拡張（別のライセンス）を1つのアプリにまとめることがある。アプリの「このアプリについて」と第三者の表記に両方のライセンスを書く。ソースからビルドしたものには拡張が入らず、それだけで完全に使える。
3. **本体は今後もどこにも接続せず、キーを確認しない**。本体のコードは、ライセンスの確認・作者のホストへの接続・テレメトリを持たない（ADR 0008 の決定 2 のとおり。更新確認の例外も今のまま）。「拡張が使えるか」の判定も本体に置かない。判定・接続が要るなら拡張の中で行い、その接続先は拡張の設定の節と公開の README に書く。
4. **本体のコード・ドキュメントには拡張の中身を書かない**。本体では「拡張（extension）」とだけ書き、拡張点の名前は機能に寄せず一般的にする（`todayNotices`、`launcher`、`power.keepAwake` など）。拡張点の確かめは、本体の中のテスト用の拡張（`test/ext-fixture/`）で行う。
5. **UI の価格・アップグレードの規則**（design-system.md）: 本体の UI には価格・試用・アップグレードの案内を出さない（今までどおり）。拡張は自分の設定の節を持てるが、価格は出さず、押し売りの表示（鍵の印・繰り返しの案内）をしない。

## Consequences

- 公開のビルドの動作は変わらない（拡張の一覧が空。テストで確かめる）。拡張を組み込んだビルドだけ、拡張の画面・テーブル・ルートが増える。
- 拡張のテーブルは本体のマイグレーションと別に管理するので、拡張を組み込んだビルドで使った DB を、拡張なしのビルドで開いても動く（拡張のテーブルは使われずに残る）。
- 拡張点の型は公開の API になるので、変えるときは `EXT_API_VERSION` を上げる。版の合わない拡張は組み込まない（デーモンはログに残して読み飛ばし、Web はコンソールに出して読み飛ばす）。
- 「データは端末の外に出ない」の説明に、「公式の配布物に拡張が入っている場合、その拡張が書いた接続先」が加わる。README のプライバシーの節に書く。
- フォークで拡張の判定を外されることは前提として受け入れる（外されて困るものは公開リポジトリに無い）。

## 追記（2026-10-11）: 足した拡張点

決定 1 の一覧に、Web の「一日を閉じるの手順（自分の番と日報の間）・サイドバーの下の1行・メニューバーのポップオーバーの1行」と、デーモンの部品「電源とふたの状態（読むだけ）・Claude の利用枠（本体が起動したセッションの statusLine から読んだ値）」を足す。どれも拡張の中身を本体に書かず、名前は一般的にした（決定 4）。版の扱いは ADR 0017 の追記、中身は [m2-api.md](../spec/m2-api.md) 28 章。
