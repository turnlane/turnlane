# ADR 0005: AI セッションの会話本文は保存も送信もしない

- ステータス: Accepted（Amended by 0018: 「送らない」はそのまま、「保存しない」は限定した待ちの中身の保存に置き換えた。2026-10-03・2026-10-08・2026-10-16（2 件）・2026-10-17 追記あり。末尾。Decision の「LLM による要約」の項と「パース直後に破棄する」、Consequences の「詳細パネルで会話の中身は表示できない」、2026-10-16 の追記の「通知には中身を出さない」を補正）
- 日付: 2026-10-02

## Context

- AI セッションの会話本文、プロンプト、ツール入出力には、社内コード、顧客情報、貼り付けられた API キーなどの機密が含まれうる。
- dayline に必要なのは「いつ、どのリポジトリ・ブランチで、どの状態だったか、何分かかったか、PR は何か」というメタデータであり、本文は不要。
- 本文を持たなければ、同期・バックアップ・ログ・エクスポートのどこからも漏れない。勤務先の情報セキュリティ規程との衝突も避けやすい。

検討経緯は非公開の戦略ドキュメントにある。

## Decision

- 会話本文を dayline の DB、ログ、spool、エクスポート、バックアップのいずれにも**保存しない**。ネットワークにも**送信しない**。
- 各アダプタは「読んでよいキー」を許可リストで宣言し、それ以外（`message.content`、`prompt`、`text`、`last_agent_message`、`last_assistant_message`、`tool_input`、`initialMessage`、`systemPrompt`、`emailAddress` など）はパース直後に破棄する。hooks の本文は hook コマンド内で破棄する。
- 判定に本文の性質が必要な場合（例: 最終メッセージが質問で終わるか）は、パース中にその場で判定し、真偽値だけを残す。
- 例外としてツールが生成したタイトル（`ai-title`、`thread_name` 等）は表示のために保存する。ただし「タイトルも保存しない（ブランチ名のみ）」モードを用意する。
- 認証情報を含むファイル（`auth.json`、`*.key`、`Cookies*`、`*token*` など）は開かない。パターンをハードコードする。
- ログ関数は型でメタデータしか受け取れないようにする。
- 検証として、本文フィールドに番兵文字列を埋めたフィクスチャを取り込み、DB（WAL を含む）・ログ・エクスポートのいずれにも番兵が出ないことを CI で常に確認する。`dl doctor` は長文フィールドを監査する。
- LLM による要約はオプトインとし、入力はメタデータに限る。既定はローカル LLM。

## Consequences

- 詳細パネルで会話の中身は表示できない。本物を見たいときは「ターミナルで再開」などの導線で元ツールへ移動させる。
- 将来の同期でも AI 系データは `local_only` が既定で、同期する場合もタイトル・状態・時刻などメタデータに限る。
- 許可リストの保守（ツールの形式変更時のキー追加）と、番兵テストの維持が必要になる。
- 本文を使った高度な要約・検索機能は作らない。

## 追記（2026-10-03）: 日報の AI 要約（Amended）

Decision の「LLM による要約はオプトインとし、入力はメタデータに限る。既定はローカル LLM。」を、日報の AI 要約について次のように補正する（PO 決定 D-041）。会話本文を保存も送信もしないという決定はそのまま有効。

### Context

- 日報はテンプレートで事実を並べるだけで、「今日は何だったか」という意味付けが無い。意味付けがタスク管理の価値になる。
- dayline はサーバーを持たない（ADR 0008）。利用者の多くは Claude Code か Codex をすでに自分のアカウントで使っている。ローカル LLM を既定にすると、モデルの導入と配布の負担が利用者と dayline の両方に増える。

### Decision

- 日報の AI 要約は**オプトイン**（既定オフ）とし、**ユーザー自身が入れている `claude` / `codex` の CLI をローカルで子プロセスとして呼んで**作る。dayline 自身はネットワークに出ない。要約は選んだツールが、ユーザーのアカウントで提供元（Anthropic / OpenAI）へ送って作る。ローカル LLM は既定にしない（将来、同じ枠で選べるようにしてよい）。
- 渡すのは**固定のプロンプトと日報の Markdown だけ**とする。日報に含まれるのはタスク名、AI 項目のタイトル（ツールが生成したタイトル。保存しないモードでは含まれない）、リポジトリ名、PR 番号、時間、ユーザーが書いた Note。会話本文・プロンプト・ツール入出力は dayline が持っていないので渡しようがないが、要約の組み立て関数の入力型を日報の Markdown 文字列だけにして構造で守る。
- 有効にするとき、送る内容と送り先を画面で説明する。
- 呼び出しはツールを使わせない・セッションを保存しない起動フラグを付け（版に無ければ付けない）、要約専用の作業ディレクトリで実行し、そのディレクトリを取り込みの除外ルールに入れる（要約の実行が AI 作業として数えられないように）。
- タイムアウト（既定90秒）・CLI が無い・失敗のときは要約なしで日報を保存する。CLI の stdout / stderr はログに書かない。
- 要約の結果は日報と同じ扱い（DB の `daily_note` に保存し、エクスポートとバックアップに含む）。

### Consequences

- 要約を使う利用者の日報のメタデータ（タイトル、リポジトリ名など）は、その利用者が選んだ提供元へ送られる。送るかどうかは利用者が決め、既定では送らない。README のプライバシーの節（M6-2）に書く。
- dayline は CLI の起動フラグと出力に依存する。ツールの更新でフラグが変わったら検出時の確認で外し、作業ディレクトリの除外で補う。
- 番兵テストに「要約の子プロセスの stdin に日報以外が入らない」を足す。
- 実装の仕様は phase0-plan の M4-6。

## 追記（2026-10-08）: タスクから AI に頼む（Amended）

PO 決定 D-107・D-109。会話本文を保存も送信もしないという決定はそのまま有効。

- タスクから AI に頼むと、**利用者が書いたタスクの題名・メモと、依頼のときに書いた指示**を、利用者のいつもの端末で起動した `claude` / `codex` の最初のプロンプトとして渡す。送り先は利用者が選んだツール（利用者のアカウント）で、dayline 自身はネットワークに出ない。D-041 の日報の要約と同じく、利用者の操作（依頼のボタン）があったときだけ。
- 組み立てたプロンプトと指示は、`dl ai run` が受け取るまで（2分）デーモンのメモリにだけ置き、DB・ログ・エクスポートには入れない。DB の `ai_launch` に残すのは依頼のメタデータだけ（ADR 0014）。
- 起動した AI のセッションの本文は、これまでどおり取り込まない（allowlist は変えない）。紐づけはセッション ID・cwd・時刻だけで行う。
- 確認支援の差分は量（ファイル数・行数・コミット数）だけを git から読み、本文は読まない・送らない。差分の文章での要約（AI に差分を渡す）は入れていない（入れるときは日報の要約と同じオプトインと説明を付ける）。テストのコマンドの出力（利用者のテストの出力）は最後の50行をメモリにだけ持つ。

## 追記（2026-10-16）: 表示の瞬間にだけ手元から読む（Amended）

PO 決定 D-206・D-207。**保存しない・送らない**という決定はそのまま有効。「パース直後に破棄する」と Consequences の「詳細パネルで会話の中身は表示できない」を次のように補正する。

- 自分の番の行・メニューバー・詳細パネルに「なぜ待っているか」を出すため、**表示の瞬間に**手元のセッションの記録から 1〜3 行だけ読む（`GET /api/work-items/:id/glance`）。読むのは、許可を求めているツールの呼び出し（Bash のコマンドと Claude の短い説明、Edit / Write / Read はパスだけで中身は読まない、WebFetch は host と path、MCP はツール名と引数のキー名だけ）、最後のメッセージの問いの文（2 文まで）、AskUserQuestion の問いと選択肢、件名に使う直近の自分の指示の 1 行目。
- 取り込みのパーサが持つのは**行の位置（バイト数）と真偽値（題名に使える指示か）だけ**（`ingest_cursor.carry_state_json`）。本文は今までどおりパース直後に捨てる。
- 読んだ中身は HTTP の応答（`Cache-Control: no-store`）にだけ入れる。DB・WAL・ログ・spool・SSE・MCP・通知・日報と記録・エクスポート・バックアップには入れない。glance のモジュールはロガーを受け取らず、JSON のパースのエラー文も返さない（理由のコードだけ）。画面のキャッシュはメモリだけで 30 秒。
- **通知には中身を出さない**。macOS は通知の内容を通知センターに保存するため。通知の題名は件名（自動の題名。表示の瞬間に読んだ指示は使わない）、副題は待ちの種類 · リポジトリ。
- コマンド・問い・指示は表示の前に伏せ字を通す（決まった前置きの鍵、`Bearer`・`Authorization:` の値、URL のユーザー情報とクエリの値、名前に TOKEN・SECRET・PASSWORD などを含む代入の値、`--password` などの値、でたらめな長い文字列）。完全ではないので、Claude の短い説明をコマンドより先に出す。再表示のボタンは作らない。
- 設定「行に中身を出す」（`turn.show_detail`、既定オン）でオフにでき、オフなら記録を読まない。今は Claude Code だけ（Codex は後から）。

### Consequences

- 番兵テストを広げた: glance の応答には番兵が出ること、その後も DB（WAL）・ログ・エクスポート・spool・SSE で流れたもの・MCP の各ツールの出力・日報に番兵が無いこと、応答が no-store であること。
- 記録の内部形式が変わったら「読めなければ出さない」に倒す（状態の判定には影響しない）。
- 画面共有の上に中身が出うる。設定でオフにできることを設定の説明に書く。

## 追記（2026-10-16 の 2）: 件名の読み直しを待っていない項目と通知の題名へ広げる（Amended）

PO 決定 D-210・D-211。**保存しない・送らない**という決定はそのまま有効。上の追記（2026-10-16）の「件名に使う直近の自分の指示の 1 行目」を読む場所と、「通知には中身を出さない」を次のように補正する。

- **待っていない項目にも件名だけ読む（D-210）**: AI の詳細パネルの見出しと、AI の線（3日ボード・デイビュー）のラベルとホバーも、表示の瞬間に直近の意味のある指示の 1 行目を読んで件名にする（`GET /api/work-items/:id/glance` は待っていない項目でも `prompt` だけ返す）。件名の順は 自分で付けた名前 → （PR の確認待ち・マージ待ちだけ）PR の題名 → 直近の指示 → ai-title → ブランチ → リポジトリ。読むもの・伏せ字・保存しない範囲は上の追記と同じ。
- **通知の題名も直近の指示にする（D-211）**: ai-title はセッションの間ずっと同じなので、通知が古い話題の題名で出ていた。即時の通知（許可待ち・返答待ち・エラー）の題名を、直近の意味のある指示の 1 行目（短い返事を飛ばし、伏せ字と 120 文字の切り詰めを通したもの）にする。
  - デーモンの `notify`（SSE）に入れるのは「差し替えてよい」という真偽値（`promptTitle`）だけで、指示の中身は入れない。デスクトップアプリが**通知を出す直前に** glance を読み、`prompt` があれば題名にして macOS の通知に渡す。アプリは読んだ中身を覚えず、ログに書かない。DB・ログ・SSE・MCP・記録・エクスポートには今までどおり入れない。
  - 中身を運ぶのは macOS の通知だけになる。macOS は通知の内容を通知センターに保存するので、指示の 1 行目は通知センターに残る（コマンド・AI の問いは今までどおり通知に出さない）。
  - 設定「行に中身を出す」（`turn.show_detail`）がオフなら glance は記録を読まないので、題名は今までの件名（名前 → PR の待ちは PR の題名 → ai-title → ブランチ → リポジトリ）のまま。読めないときも同じ。設定「通知に出す中身」が「件名も出さない」なら読まない。
  - 自分で付けた名前のある件は読まない。副題（待ちの種類 · リポジトリ）・本文（ブランチ）・まとめの通知（件数と `件名 — 待ちの種類`）は変えない（D-207）。ブラウザ通知（アプリが無いとき）も変えない。

### Consequences

- 通知センターに指示の 1 行目が残る。消したいときは設定「行に中身を出す」をオフにする（行の中身と通知の題名の両方が止まる）ことを設定の説明に書く。

## 追記（2026-10-17）: PR の題名を件名から外す・まとめの通知も表示の瞬間に読む（Amended）

PO 決定 D-214 (1)。**保存しない・送らない**という決定はこの追記の時点ではそのまま有効（件名をその日の最初の指示に固定するのは、限定した保存を入れる D-218 の別の変更で行う）。上の追記 2 を次のように補正する。

- **PR の題名は件名にしない**: PR の確認待ち・マージ待ちでも、件名は 自分で付けた名前 → 直近の意味のある指示 → ai-title → ブランチ → リポジトリ。PR の題名は理由の行（`PR #190 題名`）に出す。glance は PR の待ちでも直近の指示を読む。
- **まとめの通知も出す直前に読む（D-211 の範囲を広げる）**: デーモンの `notify`（SSE）のまとめの通知には、本文の行ごとに「差し替えてよい項目の ID と行の後ろの言葉（` — 待ちの種類`）」（`promptLines`）だけを入れ、指示の中身は入れない。デスクトップアプリが出す直前に各項目の glance を読み、`prompt` があればその行を差し替える。読めない行・自分で付けた名前の行・「件名も出さない」の設定はデーモンの行のまま。
- 今日閉じた一覧の件名も、表示の瞬間に glance を読む（行と同じ件名）。記録（日報・`turnlane report`・MCP・書き出し）は今までどおり ai-title のまま。

### Consequences

- macOS の通知センターに残る指示の 1 行目は、即時の通知に加えてまとめの通知の分も増える（止める方法は同じく設定「行に中身を出す」のオフ）。

## 追記（2026-10-18）: PR の題名を ai-title の下・ブランチ名の上に戻す（Amended）

fix-subject-pr。上の 2026-10-17 の追記の「PR の題名は件名にしない」を次のように補正する。保存しない・送らないの範囲は変えない（PR の題名は gh から読む値で、会話の本文ではない）。

- 件名の順は 自分で付けた名前 → その日の最初の指示 → ai-title → **PR の題名** → ブランチ → リポジトリ。指示も ai-title も無いカード（別のディレクトリのセッションが出した PR だけのカード。ターンが無い）で、ブランチ名を空白で区切った件名になっていたのを直す。
- AI の問い・許可を待っている間は PR の題名を件名にしない（D-213）。
- 件名が PR の題名のときは理由の行で題名を繰り返さない（`PR #8 · 2 ファイル · +12 −8 · CI 通過`）。
