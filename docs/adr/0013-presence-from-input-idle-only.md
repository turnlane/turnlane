# ADR 0013: 在席は「最後の入力からの経過」だけで記録し、放置は在席の間だけ数える

- ステータス: Accepted（2026-10-09 追記あり。末尾。Decision 4 の保存の形を補正）
- 日付: 2026-10-08
- 関係: PO 決定 D-105・D-106・D-110。勤務時間（D-018・D-063・D-079・D-082・D-084 の勤務時間の部分）を置き換える。設計の詳細は [phase0-plan.md](../spec/phase0-plan.md) 3.3.1（在席と時間の計算）・2.3 の DDL（`presence_span`）、[m2-api.md](../spec/m2-api.md)、[ux-mvp.md](../spec/ux-mvp.md)。会話本文を持たない方針は [ADR 0005](./0005-no-ai-session-body-storage-or-transmission.md)、外部へ送らない方針は [ADR 0008](./0008-mit-no-server-open-source.md)

## Context

- 放置（AI が待っている時間のうち、自分が応答しなかった時間）は、これまで「勤務時間」（その日の最初の操作から最後の操作まで、閉店で終わり、手で直せる）の内側だけで数えていた。勤務時間は勤怠のように見え、背景のパネル・稼働開始の線・日報の勤務時間・空白で勤務日を分ける設定など、画面と仕組みが大きくなった。
- オーナーは勤怠を管理したいわけではない（D-105）。数えたいのは「Mac の前にいたのに AI を待たせていた時間」で、昼休み・夜・離席は自然に外れてほしい。
- macOS は「最後のキーボード・マウスの入力からの経過秒数」を権限なしで返す（`CGEventSourceSecondsSinceLastEventType`、`ioreg` の `HIDIdleTime`）。入力の中身・アプリ名は読まずに済む。
- 実装計画（tech-architect の調査）で、デーモン（LaunchAgent）から 30 秒ごとに読む方式を推奨した。カレンダーヘルパ（使わない人がいる）やデスクトップアプリ（起動していないことがある）に持たせる案、入力監視（CGEventTap。権限が重く中身を読める）は採らなかった。

## Decision

1. **在席の取り方**: デーモンが 30 秒ごとに「最後の入力からの経過」を読む。まず Bun FFI で CoreGraphics の `CGEventSourceSecondsSinceLastEventType(kCGEventSourceStateHIDSystemState, kCGAnyInputEventType)` を呼び、使えなければ（JIT の無い署名、失敗）`/usr/sbin/ioreg -c IOHIDSystem` の `HIDIdleTime` を読む。あわせて `ioreg -n Root -d1` の `IOConsoleUsers` から、このプロセスの uid の項目の `CGSSessionScreenIsLocked`（画面ロック中）と `kCGSSessionOnConsoleKey`（別ユーザーに切り替え中は No）を読む。入力監視・アクセシビリティの権限は要らない。
2. **取るもの・取らないもの**: 取るのは最後の入力からの経過（秒）と、ロック中か・コンソールにいるかの2値だけ。どのキーを押したか、ポインタの位置、どのアプリ・ウインドウを使っていたかは読まない・保存しない。
3. **在席の定義**: 最後の入力から T 分（設定 `presence.tail_min`、既定 5 分、2〜15 分）までを「Mac を使っていた」とする（読む・考える時間を拾う余白）。区間の終わりはサンプルの時刻を超えない（スリープの直前に操作しても眠っている間を在席にしない）。次のサンプルで前の入力からの続きを足す。前のサンプルから 2 分以上空いた（スリープ・デーモンの停止）ら、その間は不在とし、空いた後は前のサンプルより後の入力だけを証拠にする。画面ロック中・別ユーザーに切り替え中は不在。
4. **保存**: 区間の始まりと終わりだけを `presence_span`（端末内だけ。同期しない・`mutate()` を通さない・変更ログなし）に保存する。重なる・接する区間は延ばすので1日数十行に収まる。外部には送らない（ADR 0008）。
5. **放置の数え方**: 待ちの区間から、一日を閉じていた区間（`closed`）→ 在席の外（`away`）→ busy な予定（`event`）→ タスクなし → スヌーズ → 時間に置いた開始の前 の順で除き、残りを猶予（数えうる時間に入ってから最初の 15 分。D-058）と放置にする。勤務時間（`work_day_auto`・手で直した勤務時間・空白で勤務日を分ける規則・いつもの勤務時間）はなくす。
6. **一日を閉じる**: 閉店から「次の論理日の始まり（日付区切り、既定 4:00）より後で最初に在席した時点」までを `closed` とし、放置に数えない。閉店モードの通知の停止も同じ時点で解く。「再開」で閉店を解けばそこで終わる（D-110 (1)）。
7. **過去の値**: 在席の記録を始めた時刻を `idle.presence_since` に残し、その論理日より前の待ち区間は作り直さない（D-110 (3)）。マイグレーション 0009 は既存の待ち区間を残し、`off_hours` を `away` に読み替える。
8. **計画の目安**: 曜日ごとの計画上の時間（設定キー `work_hours.planned` のまま）は「計画の目安」として、空き時間と「明日朝」のスヌーズにだけ使う。放置の計算には使わない（D-106）。

## Consequences

- 昼休み・離席・夜は自然に放置から外れ、勤務時間の行・編集・背景のパネル・稼働開始の線・日報の勤務時間・勤務日を分ける設定が消える。時間軸の背景は一様になる。
- 入力のない作業（長い文書を読む・紙で考える）は T 分を過ぎると不在になり、放置は少なめに出る。T は設定で変えられる。
- マウスを動かし続けるアプリや `caffeinate -u`（利用者の操作があったと宣言する）を使うと、無人でも在席に見える（放置が多めに出る）。README に書く。
- コンパイル済みの daylined は hardened runtime の `allow-jit` で FFI を使える（S-A1。ad-hoc 署名の同じ条件のバイナリで確認）。JIT が無い環境では ioreg（1回 十数 ms）に切り替わる。LaunchAgent から起動した状態での読み取りは、入れ替え後に `presence.method` のログで確かめる。
- 在席の記録を始めた日は、その時刻より前が不在になるので、その日の放置は少なめに出る（その1日だけ）。それより前の日の放置は勤務時間の規則で数えた値のまま残る。

## 追記（2026-10-09）: 在席は入力のあった区間で保存し、T は読むときに足す（Amended。PO 決定 D-139）

### Context

Decision 4 の実装では、区間の終わりに T（`presence.tail_min`）を足して保存していた。そのため設定を変えると過去と未来で規則が混ざり、過去の日を別の T で数え直せず、T より短い入力の間も残らなかった。

### Decision

1. `presence_span` には入力のあった区間を保存する。`start_at` は最初の入力、`end_at` は最後の入力の時刻、`seen_until` はその最後の入力から途切れずに見ていた最後のサンプルの時刻。入力の間が 2 分（T の下限）以内なら同じ区間を延ばし、それより長ければ新しい区間にする
2. T は読むとき（放置・不在の判定、閉じた日の明け、朝の再開、日の確定、拡張点の在席）に今の設定で足す。各区間は `[start_at, min(end_at + T, seen_until)]` で、重なれば和集合にする。Decision 3 の在席の定義は変えない（同じサンプルの列から、どの T でも以前と同じ在席になる）
3. デーモンを再起動したとき、前回の最後の区間を 2 分以内まで見ていたなら、その続きとして扱う（再起動のたびに最後の入力の後が切れていた）
4. マイグレーション 0014 は既存の行の終わりから T を引く。書いた時点の T は記録に無いので今の設定（無ければ既定の 5 分）を使う。T より短い区間と最後の区間は元の終わりを `seen_until` に入れ、ほかは `seen_until` を NULL（上限なし）にする。同じ T で読めば元の区間に戻る

### この追記の Consequences

- 設定を変えると、作り直す範囲（`turnlane rederive` の対象）の日は新しい T で数え直す。0014 より前の行は、T を短くすると終わりを縮め（実際の入力の間は分からないので上限の値）、長くすると延ばす（スリープで切れていても延びる）
- 1 回だけ触れた区間の扱いは変えない（1 週間分のデータで見直す）
