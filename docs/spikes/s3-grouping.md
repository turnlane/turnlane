## 結論

1. **phase0-plan 3.3 のグルーピング規則はおおむねそのまま使える。** 1つのセッションが10枚のカードに分かれ、PR を作った9枚はすべて「1ブランチ = 1 PR = 1カード」になった。ただし、そのまま実装すると誤る点が3つある。
   - `pr-link` は同じ PR がセッション中に何度も再出力される（45 PR に対して 978 レコード）。ターンごとに拾うと、1カードに複数 PR が付くケースが10件、review_pr が24件出た（正しくは1件と10件）。**初出のレコードだけを PR 作成として扱い、PR のカードへの帰属は `gh` の `headRefName` で決める**必要がある。
   - ターン内でブランチが変わることがある（Claude のターンの13%）。**ターンのブランチは終了時点の `gitBranch` にする。** PR の head ブランチと一致したのは、終了時点のブランチが 9/10、開始時点が 1/10 だった。
   - `ai-title` はセッションごとに固定で、途中で変わらない（12セッション中11が1種類、1が無し）。**複数ブランチにまたがるセッションでは、全カードが同じタイトルになる**（21枚中10枚が他カードとタイトル重複）。ブランチのカードでは PR タイトルかブランチ名を ai-title より優先する必要がある。
2. **状態判定は「done」と「your_turn」の境界に仕様の穴と過剰判定がある。** your_turn 5件はすべてセッション単位のカード（既定ブランチか git 管理外）で、根拠は「最終ターンで編集あり」3件と「質問で終了」2件。編集ありの規則は時間切れが無いので、git 管理外のディレクトリで編集したカードが your_turn のまま残り続ける。
3. **`turn_duration` はほぼ全ターンにある**（Claude 105/107 = 98%、欠けた2件はどちらもユーザー中断）。Codex は `task_complete` / `turn_aborted` の `duration_ms` が 28/28 にある。AI 時間の代替計算はほとんど要らない。
4. **reply フォローアップは即時生成するとノイズになる。** 27件生成し、25件は人間の次の入力で自動クローズされた。AI のターン終了から次の入力までの中央値は4分。猶予時間を置いて生成する方がよい。
5. **Codex の SQLite（`state_5.sqlite` / `thread_history_1.sqlite`）は、`bun:sqlite` の readonly でも sqlite3 CLI の `mode=ro` でも開けなかった**（`unable to open database file`）。JSONL へのフォールバックで必要な値はすべて取れた。原因の切り分けは S2 に任せる（→ S2 で原因が分かり、Phase0 の Codex 取り込みは JSONL のみに決まった）。
6. オーナー確認の結果、**粒度の分けすぎ・まとめすぎは無かった**。状態の誤り率は、★を付けた行の個別確認が未記入のため数値にできていない（全体の質問では粒度の誤りなし）。見落としは「Claude の別アカウント（名前に `work` を含む設定ディレクトリ）の作業」で、本スパイクがその設定ディレクトリを対象外にしたことによる。詳細は末尾の「オーナー確認の結果」。

## グルーピング規則の調整案

1. **`pr-link` は初出だけを使う。** セッション内で `(prRepository, prNumber)` が初めて出たレコードを PR 作成とみなし、そのターンに紐付ける。2回目以降は無視する。
2. **PR のカードへの帰属は head ブランチで決める。** `gh` から取った `headRefName` に一致する `branch:<repo>#<head>` のカードに付ける。そのカードが無いとき（そのブランチで終わったターンが無い）は、ターンではなく PR を起点に `branch:<repo>#<head>` のカードを作る方が自然。今回のフォールバック（初出ターンのカード）は誤帰属を1件生んだ。
3. **ターンのブランチは終了時点の `gitBranch`。** 最長滞在ブランチとの差は1ターンだけで、PR との一致は終了時点が最も良い。
4. **既定ブランチの「つなぎ」ターンの扱いを決める。** 案: 同じセッションが branch のカードを1枚以上持つ場合、既定ブランチで終わったターンは直後の branch カードに寄せる（直後が無ければ直前）。オーナー確認の結果で採否を決める。→ **不採用**。オーナー確認で粒度の誤りは無いとの回答だったため、つなぎのターンは session のカードのままにする。
5. **タイトルの優先順位をカードの種類で変える。** branch のカードは「PR タイトル → ブランチ名の整形 → ai-title」、session のカードは「ai-title → …」。ai-title はセッションで固定なので、ブランチをまたぐセッションでは使い回しになる。
6. **cwd が消えたターンの repo を補う。** ディレクトリ名を変えると、過去のターンの repo が解決できなくなる（12ターン）。常駐取り込みでは取り込み時に解決して保存するので問題になりにくいが、初回のバックフィルでは起きる。同じセッション内で直前に解決できた repo を引き継ぐ、を補助規則にする。
7. task-notification を起点とするターンは AI 時間に数えるが、人間入力としては扱わない（返答待ちを解除しない、待ち時間の終点にしない）。
